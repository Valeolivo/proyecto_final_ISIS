# Sprint Retrospective — Evaluación del Equipo

**Proyecto:** Aplicación Web Educativa para Adultos Mayores (CLENA)

**Fecha:** 29 de septiembre de 2026

**Facilitadora:** Valery Romero Mendoza (Scrum Master).

## 1. Objetivo de la reunión

Evaluar el proceso de trabajo del equipo durante el Sprint, reconocer las prácticas que facilitaron el cumplimiento de las actividades, identificar aspectos por mejorar y establecer acciones concretas para optimizar la organización y colaboración en futuros laboratorios.

## 2. ¿Qué hicimos bien?

### 2.1. Claridad en la división de roles

La definición específica de tareas entre Product Owner, Scrum Master, Development Team y responsable de evidencias optimizó el tiempo de trabajo.

### 2.2. Enfoque centrado en el usuario

Se priorizó el análisis de la autonomía digital del adulto mayor antes de iniciar el diseño en Figma.

### 2.3. Seguimiento efectivo

 El tablero Kanban en GitHub Projects y las reuniones en Microsoft Teams permitieron identificar cuellos de botella a tiempo.

## 3. ¿Qué podríamos mejorar?

* Optimizar el tiempo necesario para redactar y clasificar detalladamente las descripciones de las evidencias multimedia.
* Mejorar la convención de nombres y mensajes de commit al momento de enviar cambios a través de Git/GitHub.
  
## 4. Plan de acción y compromisos

* Establecer plantillas previas para la redacción de evidencias en futuros laboratorios.
* Mantener la disciplina en el registro periódico de actividades en el tablero Kanban y el uso de ramas para nuevas funcionalidades.

## 5. Acuerdos

1. Establecer plantillas previas para la redacción de evidencias en futuros laboratorios.
2. Mantener la disciplina en el registro periódico de actividades en el tablero Kanban.
3. Mejorar la organización de los cambios mediante el uso de ramas para nuevas funcionalidades.
4. Fortalecer las convenciones de nombres y mensajes de commit en Git y GitHub.

## 6. Conclusión

La retrospectiva permitió reconocer que la claridad en la división de roles, el enfoque centrado en el usuario y el seguimiento mediante GitHub Projects y Microsoft Teams fueron aspectos positivos del trabajo del equipo, asimismo, se identificaron oportunidades de mejora relacionadas con el tiempo dedicado a la clasificación y descripción de evidencias multimedia y con la consistencia de los nombres y mensajes de commit.Como resultado, se establecieron acciones de mejora orientadas a utilizar plantillas para las evidencias, mantener actualizado el tablero Kanban y utilizar ramas para nuevas funcionalidades en futuros laboratorios.

## 7. Compromisos para futuros laboratorios

* Implementar plantillas para documentar y clasificar las evidencias multimedia.
* Registrar periódicamente las actividades en GitHub Projects.
* Mejorar la convención de nombres y mensajes de commit.
* Utilizar ramas para organizar el desarrollo de nuevas funcionalidades.
